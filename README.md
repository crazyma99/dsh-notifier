# dsh 任务状态通知

一个 Chromium 浏览器扩展：监听 **dsh**（DeepSeek Harness）Web GUI 的会话状态，在**任务开始 / 完成 / 等待授权或回答 / 出错**时，通过操作系统通知提醒你。

由浏览器所在的系统发送通知，因此 **Windows / Linux / macOS 通用**——包括 dsh 跑在 WSL 或远程服务器、而浏览器在桌面系统上的情况。

- **本机数据**：只读取你明确授权的那一个 dsh 地址，不发起任何网络请求，不上传任何内容。
- **可配置地址**：本地 `http://127.0.0.1:3080`、内网服务器、SSH 隧道地址均可。
- **界面**：Material Design 3（Material You）动态配色，种子色可自选。

---

## 特性

| 能力 | 说明 |
| --- | --- |
| 四种通知时机 | 开始运行 / 任务结束 / 等待你的授权或回答 / 出错或需要关注，可分别开关 |
| 不打扰策略 | 默认在你正看着 dsh 页面时不通知；同一会话同类事件有静默间隔，避免刷屏 |
| 多会话 | 按会话分别跟踪状态，通知标题就是会话名称 |
| 徽标 | 扩展图标显示正在运行的会话数；有等待你操作的地方时显示红色 `!` |
| 一键回到现场 | 点击通知即可把 dsh 标签页切到前台 |
| 自行诊断 | 弹窗内置「诊断当前页面」，识别不成功时直接给出页面 DOM 事实与当前识别结果 |
| 可调识别规则 | 选择器与关键词都在设置页「高级」里，dsh 前端改版时改配置即可，无需改代码 |
| 动态配色 | 由种子色按 Material 3 色调板推导整套浅色 / 深色配色 |

## 环境要求

- **浏览器**：Chrome 111+ 或其它 Chromium 内核浏览器（Edge、Brave 等）。使用的是 Manifest V3 与 `chrome.*` API，Safari 不支持。
- **dsh**：识别依赖 dsh 前端的一组语义化 DOM 标记（见[工作原理](#工作原理)）。
- **系统通知**：需要在系统里允许浏览器发送通知（见[故障排查](#故障排查)）。

## 安装

1. 打开 `chrome://extensions`，右上角开启**开发者模式**。
2. 点击**加载已解压的扩展程序**，选择本扩展所在目录。
3. 点击工具栏里的扩展图标 → **设置**，进入选项页。

> 若通过压缩包分发：解压后按上述步骤加载即可，目录不要删（扩展直接引用该目录的文件）。

## 快速开始

1. 在设置页确认**监控地址**（默认 `http://127.0.0.1:3080`）。
2. 点击**保存并启用监听**。浏览器会弹出该地址的访问权限申请，同意即可。
3. 点击**重载 dsh 标签页**（或手动刷新）。
4. 点击**发送测试通知**，确认系统通知通道正常。
5. 打开弹窗，应能看到 dsh 里的会话列表及各自状态。

之后正常使用 dsh 即可：任务在你没盯着页面时结束，就会收到通知。

## 配置项

### 监控地址

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| dsh URL | `http://127.0.0.1:3080` | 形式为 `协议://主机:端口`。地址需与你在浏览器里实际打开的 **origin 完全一致**：`127.0.0.1` 与 `localhost` 在浏览器看来是两个不同的来源。 |

### 通知时机

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| 任务完成 / 结束运行时通知 | 开 | 会话从"运行中"回到"已完成"或"空闲"时提醒 |
| 等待你的授权或回答时通知 | 开 | 出现授权确认或提问界面时提醒，通知会尝试驻留以便你处理 |
| 出错或需要关注时通知 | 开 | 会话进入出错或需要关注状态时提醒 |
| 任务开始运行时通知 | 关 | 默认关闭以避免噪音 |
| 即使我正在看 dsh 页面也通知 | 关 | 默认情况下，dsh 页面处于前台时不打扰 |
| 同类事件静默间隔 | 15000 毫秒 | 同一会话同类事件的去抖时间 |
| 页面轮询间隔 | 3000 毫秒 | 心跳采集间隔；DOM 变化会即时触发，不依赖轮询 |

### 外观

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| 种子色 | `#6750A4` | Material You 动态配色：整套深浅色由它推导，另有 6 个预设 |
| 明暗模式 | 跟随系统 | 可切换跟随系统 / 浅色 / 深色；跟随系统时会随系统外观即时切换 |

### 调试与高级

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| 采集浮层 | 关 | 在 dsh 页面右下角显示实时采集结果，用于确认识别是否正常 |
| 会话行选择器 | `[data-row-key^="session:"]` | 识别会话行的主锚点 |
| 状态文案 | 进行中 / 空闲 / 已完成 … | 用于从行文本中剔除状态文字 |
| 授权提示关键词 | 允许一次 / 拒绝 / 批准 / Approve … | 与"界面里带按钮"共同判定授权请求 |
| 提问提示关键词 | 请选择 / 等待你的回答 … | 同上，用于提问面板 |

## 工作原理

```text
dsh 页面（Web GUI）
  └─ 内容脚本   采集语义化 DOM → 快照 { 会话[], 等待介入, 是否聚焦 }
        │  chrome.runtime.sendMessage
        ▼
  后台 Service Worker   与上一次快照比对 → 事件 → 系统通知 / 徽标
        ▲
        └─ 纯逻辑模块（可单元测试）
```

内容脚本只认**语义化标记**，不依赖样式类名：

| 目标 | 锚点 |
| --- | --- |
| 会话行 | `data-row-key="session:<会话 id>"` |
| 状态 | 行内 `[data-state]`，取值 `ongoing` / `done` / `idle` / `warning` / `error` |
| 空闲 | **没有状态圆点即视为空闲**（dsh 只在非空闲时渲染圆点） |
| 等待介入 | 带有按钮的 `role="group"` 界面，且文本命中关键词 |

**状态变化才通知**：首次看到某会话只建立基线，之后按"运行中 → 已完成/空闲"等跳变触发。若你同时打开了多个 dsh，扩展只接受**当前配置地址**的上报，其余地址的数据会被忽略并在弹窗里提示。

## 与 dsh 的部署方式

| 场景 | 需要配置的地址 | 备注 |
| --- | --- | --- |
| dsh 与浏览器在同一台机器 | `http://127.0.0.1:<端口>` | 默认值 |
| dsh 跑在 WSL，浏览器在 Windows | `http://127.0.0.1:<端口>` | WSL2 默认会把 WSL 的 loopback 转发给 Windows，通常无需额外设置 |
| dsh 跑在远程服务器 | 你在浏览器里访问它所用的那个地址 | 若通过 SSH 隧道访问，请填隧道本端的地址（如 `http://127.0.0.1:8080`） |

> dsh 的 Web 服务默认只监听 `127.0.0.1`。请勿为了图方便把它暴露到网络上——该服务本身不带 TLS，也没有网络侧认证。

## 故障排查

### 弹窗显示「未识别到会话行」

1. 确认已保存地址并刷新过页面：内容脚本只在保存之后注入，**旧页面需要刷新**才会生效。
2. 点击弹窗里的**诊断当前页面**，它会给出页面 DOM 事实（会话行数、状态取值、容器信息）与当前识别结果。
3. 依据诊断结果，到设置页「高级」里调整选择器或关键词。

### 完全收不到通知

按可能性从高到低检查：

1. **dsh 页面正在前台**：默认不打扰。切到别的窗口再试，或打开设置里的「即使我在看也通知」。弹窗会直接标出这一状态。
2. **系统通知权限**
   - macOS：系统设置 → 通知 → Google Chrome → 允许通知，并关闭专注模式。想让通知不自动消失，把提醒方式从「横幅」改为「提醒」。
   - Windows：设置 → 系统 → 通知，确认 Chrome 通知已开启且未启用专注助手。
   - Linux：需要桌面通知守护（GNOME / KDE 自带，或 `dunst`、`notify-osd`）。
3. **通知通道本身**：点**发送测试通知**。它会如实回报是否提交成功；失败时弹窗会直接给出上述处置指引。
4. **页面是否还开着**：扩展通过读取页面工作，请保持 dsh 标签页打开。

### 同时开着多个 dsh，内容似乎串了

扩展只信任**当前配置地址**。若弹窗提示"已忽略 `http://…` 的上报"，说明那个地址对应的标签页里还留着旧的内容脚本实例——刷新该标签页即可。切换监控地址时，扩展会自动刷新旧地址的标签页。

### 改了地址之后不生效

保存新地址会重新申请该地址的访问权限，并自动刷新新旧地址的标签页。若浏览器未弹出权限申请、或你拒绝了它，需要重新点击**保存并启用监听**。

### 侧边栏收起后识别不到会话

识别依赖侧边栏渲染出的会话列表，请保持侧边栏展开（可用「采集浮层」确认当前识别情况）。

## 隐私与权限

扩展**不发起任何网络请求**，不收集遥测，所有数据仅保存在浏览器本地的扩展存储中。所需权限与用途：

| 权限 | 用途 |
| --- | --- |
| `notifications` | 发送系统通知 |
| `storage` | 保存设置、外观偏好与最近一次页面快照（仅本机） |
| `scripting` | 按你填写的地址注册内容脚本 |
| 该地址的访问权限（可选权限） | 读取该页面上的会话列表；**仅在你点击保存并确认后授予，且只针对你填写的那个地址** |

## 已知限制

- **需要保持 dsh 页面打开**：扩展读取页面而非连接服务，标签页关闭后无法通知。
- **依赖 dsh 前端的 DOM 标记**：dsh 若大改前端结构，可能需要在设置页「高级」里更新选择器。
- **等待介入的判定是启发式**：依据"界面里带按钮 + 命中关键词"，文案变化时可在设置里补充关键词。
- **通知提交成功不等于一定显示**：系统权限、专注模式仍可能静默丢弃。
- **仅支持 Chromium 内核浏览器**。

## 资源重新生成

图标与默认配色是随仓库一起提交的生成物（扩展运行期直接引用它们），改动生成脚本后请重新生成：

```bash
npm run theme     # 由默认种子色重新生成 src/md3-palette.css
npm run icons     # 重新生成图标（纯标准库，无需 Pillow）
```

## 文件结构

```text
dsh-notifier/
├── manifest.json          MV3 清单（可选主机权限 + 运行时注册内容脚本）
├── src/
│   ├── decide.js          纯逻辑：快照比对 → 通知事件
│   ├── content.js         页面采集：语义化锚点 → 快照
│   ├── background.js      Service Worker：比对、通知、徽标、点击聚焦
│   ├── sources.js         多地址隔离：来源判定与分槽存储
│   ├── dom-utils.js       标题与时间文案清理
│   ├── theme.js           外观控制（种子色 / 明暗）
│   ├── md3-tokens.js      Material You 色彩引擎
│   ├── md3.css            MD3 组件样式
│   ├── md3-palette.css    生成的默认配色（首帧兜底）
│   ├── md3-controls.js    水波纹与 Snackbar
│   ├── popup.html/js      弹窗
│   └── options.html/js    设置页
├── icons/                 图标（16 / 48 / 128，已生成并随仓库提交）
└── tools/                 资源生成脚本（图标、默认配色）
```
